### Accessibility controls

Text size:
- Decrease.
- Current percentage.
- Increase.
- Display percentage such as +0%.

Text spacing:
- Allow increasing and decreasing spacing.

All other features should be actual working toggles.

### Functional requirements

- Every option must work.
- Show which options are active.
- Add a reset accessibility settings button.
- Add a clear close button.
- Support keyboard navigation.
- Support Escape to close the panel.
- Use proper ARIA labels.
- Ensure the panel works on mobile.
- Save accessibility preferences in localStorage.
- Restore the user's preferences when reopening the website.
- Do not allow accessibility settings to break the layout.
- Respect the user's reduced-motion preferences.

### Important accessibility implementation

Do not create an accessibility menu that only looks functional.

For example:
- High contrast must actually change contrast.
- Inverted colors must actually invert the page appearance.
- Grayscale must actually apply grayscale.
- Readable font must change the typography.
- Underline links must underline links.
- Highlight headings must visibly highlight headings.
- Keyboard navigation must have visible focus indicators.
- Reading ruler must actually follow the cursor or keyboard focus.
- Disable animations must disable nonessential animations.

Implement these features using a centralized accessibility context/provider and CSS classes or variables.

Create a proper keyboard accessibility experience throughout the entire website.

IMPORTANT:

An accessibility menu alone does not guarantee legal accessibility compliance. Use semantic HTML, WCAG-oriented contrast, keyboard support, screen-reader labels and proper focus management throughout the website. Do not claim certification without an actual audit.
